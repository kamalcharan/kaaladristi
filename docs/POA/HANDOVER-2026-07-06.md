## 7. Key Decisions This Session

| Decision | Detail |
|---|---|
| Score formula never disclosed | Scanner copy standard (migration 126) references only "Score 5D (money-flow conviction)" — never the formula. Hard constraint per owner, SEBI + competitive moat. |
| VaNi Opportunity formula is per-scanner but same mechanism | Each scanner has its own `vani_rule` pointing to one of 7 shared `is_vani_*` boolean rules, checking a dimension orthogonal to that scan's own filter (the "best of this list" signal) — not a single universal formula, but a single universal mechanism. |
| Pulse/Study contract | Pulse = curated 5-second verdict, never configurable, no widgets. Study = open-ended evidence, fully configurable via Catalog, no verdicts except one traveling verdict chip. Both Study surfaces (My Space, cockpit) must render identically — zero hardcoded lines, everything framework-driven. My Space's only remaining differentiators are canvas-only: instrument filter, Edit Canvas mode. |
| Big Money direction is an inference, stated as such | `classifyDirection()` in `bigMoney.ts` infers entry/exit/mixed from price behavior on the event day (up day + close in top 40% of range = entry; down day + close in bottom 40% = exit) — UI copy must never state this as fact, since delivery data itself is two-sided. |
| Quantity-based math over stored aggregate columns | Frontend derives all delivered/traded ₹ Cr from `qty × close` rather than `value_cr`/`deliv_value_cr`, which carry the 100× scale bug (§4.2). |
| Marker vocabulary | SBD=blue dot, SVD=violet dot, SYD=yellow dot, swing high/low=bare arrows. No text on any chart marker. |
