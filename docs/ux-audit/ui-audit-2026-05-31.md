## 1. Color Tokens

### Theme System (Existing — Good)
Three theme files exist in `src/config/theme/themes/`: `kaaladristi.ts`, `techAI.ts`, `jadeThorn.ts`. Each exports a `ThemeConfig` with a consistent token shape:

```
brand.primary / secondary / tertiary / alternate
utility.primaryText / secondaryText / placeholder / primaryBackground / secondaryBackground
semantic.success / warning / error / info
surface.glass / glassStrong / glassBorder
```

These resolve to CSS variables at runtime (`var(--bg)`, `var(--card)`, `var(--accent)`, etc.). The token structure is correct and complete.

### The Problem — New Components Bypass the Theme
Components added in Phase 5 (`InlineGate`, `DataQualityBar`, `PricingPage`) were written with hardcoded hex values instead of consuming the theme variables. When the theme switches from `kaaladristi` to `tech-ai` or `jade-thorn`, these surfaces will not adapt.

**Hardcoded values that should be theme tokens:**

| Component | Hardcoded Value | Should Be |
|---|---|---|
| InlineGate card bg | `#13131f` | `var(--card)` |
| InlineGate backdrop | `rgba(0,0,0,.55)` | `var(--overlay)` or theme overlay token |
| InlineGate border | `rgba(139,92,246,.35)` | `var(--accent)` with opacity |
| InlineGate "PAID FEATURE" bg | `rgba(139,92,246,.15)` | `var(--accent)` with opacity |
| InlineGate CTA button | `rgba(139,92,246,.9)` | `var(--accent)` |
| InlineGate icon tint | `#a78bfa` | `var(--accent)` |
| DataQualityBar card bg | `rgba(255,255,255,.04)` | `var(--surface-dim)` or theme surface |
| PricingPage tier cards | `rgba(255,255,255,.03)` | `var(--card)` |
| VaNi insight panels | `#0c0a1a` | `var(--bg)` |
| CorrelationDrawer overlay | `rgba(15,15,30,.95)` | `var(--card)` or theme overlay |
| VaNi onboarding orb | `#161233` | `var(--card)` |

### Risk Colors
`text-risk-green`, `text-risk-red`, `text-risk-amber` — Tailwind utility classes. Consistently used across signal vocabulary. No raw hex equivalents found. **Good — these are correct.**

### Summary
The token system exists and is well-structured. The issue is adoption: new Phase 5 components bypassed the system. Tech-AI and Jade-Thorn themes will render InlineGate, PricingPage, and DataQualityBar with the wrong dark purple aesthetic regardless of theme selection.

## 2. Typography

### Font Families in Use

|---|---|---|
| Fraunces | Display headings (brand identity) | Google Fonts via `index.html` |
| Inter | Body text, UI labels | System fallback / Google Fonts |

### Font Sizes in Use (raw px values from inline styles)
8, 10, 11, 12, 13, 14, 15, 16, 18, 20, 22, 24px — 12 distinct sizes.

### Hierarchy Problems
- No `h1 / h2 / h3` semantic pattern. WorkspacePage uses `fontSize: 22` inline for its title. CatalogPage uses Tailwind `text-xl`. DashboardV3 uses `text-2xl`. No single source of truth for heading scale.
- InlineGate uses `fontSize: 11` for the "PAID FEATURE" badge with `fontFamily: 'var(--font-mono,monospace)'` — the token fallback is inconsistent (sometimes `monospace`, sometimes omitted).
- DataQualityBar uses `fontSize: 10` for coverage label — smallest text in the product, likely inaccessible at small screen sizes.

### Flag
- Mix of Tailwind size classes (`text-sm`, `text-xs`, `text-xl`) and inline `fontSize` numbers — no consistency within pages or across pages.
- "PAID FEATURE" badge does not use `var(--font-mono)` correctly (has fallback `monospace` appended raw, not via CSS variable).

### Mobile / Responsive
