### Stage 12 — User Adds Item from Catalog

**Flow:**
1. User clicks "+ Add" on a card or "+ Add to Framework" in DeepDivePanel footer
2. `useAddToFramework` hook runs — checks tier gate (static catalog items only; astro rules bypass this hook)
3. If gated: `InlineGate` modal appears with upgrade CTA
4. If allowed: `addBlock()` or `addOverlay()` called on frameworkStore
5. `saveFramework()` debounced (800ms) → PUT to `/api/framework/{user_id}`
6. Button state changes to "✓ added" / "✓ overlay"
7. CatalogActionIsland appears/updates with new count

**VaNi:** Silent during add. WorkspaceActionIsland may update if new correlation detected.

---

### Stage 13 — User Returns Next Day (Repeat Session)

**Screen:** `/workspace` (direct, already onboarded)  
**What user sees:** Same workspace loads. `loadFramework()` fetches from `/api/framework/{user_id}`. VaNi correlations recomputed client-side from active blocks. WorkspaceActionIsland shows current correlation state.  
**VaNi:** Watching state resumes. No "welcome back" message. No session context carried over.

### Add to Framework — End to End

1. User clicks "+ Add" (card) or "+ Add to Framework" / "+ Add Overlay" (DeepDivePanel footer)
2. For **static catalog items**: `useAddToFramework(catalogItemId)` runs
   - Tier check: if `tier_required='paid'` and user not paid → `InlineGate` modal, flow stops
   - Already active: returns `reason: 'already_active'`, no-op
   - Routes by placement: `chart_overlay` → `addOverlay(item)`, else → `addBlock(item, config)`
3. For **astro rules** (from `CatalogAstroSection`): `addOverlay(item)` or `addBlock(item)` called directly — **tier gate is not applied**
4. `saveFramework()` debounced 800ms → `PUT /api/framework/{user_id}`
5. Button re-renders as "✓ active" state
6. CatalogActionIsland updates count
